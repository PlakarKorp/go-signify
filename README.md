# go-signify

[![Go](https://github.com/PlakarKorp/go-signify/actions/workflows/go.yml/badge.svg)](https://github.com/PlakarKorp/go-signify/actions/workflows/go.yml)
[![codecov](https://codecov.io/gh/PlakarKorp/go-signify/branch/main/graph/badge.svg)](https://codecov.io/gh/PlakarKorp/go-signify)
[![Go Reference](https://pkg.go.dev/badge/github.com/PlakarKorp/go-signify.svg)](https://pkg.go.dev/github.com/PlakarKorp/go-signify)

OpenBSD [signify(1)](https://man.openbsd.org/signify) as a Go library and
command-line tool.

Signatures are ed25519 over whole files, in a format that is two lines of text.
Files are wire-compatible with `signify(1)` in both directions: signatures made
here verify with the OpenBSD tool, and vice versa.

## Library

```go
import signify "github.com/PlakarKorp/go-signify"
```

Verifying:

```go
pk, err := signify.ParsePublicKey(pubkeyPEM)
sig, err := signify.ParseSignature(sigfile)

err = pk.Verify(message, sig)
```

Signing:

```go
pk, sk, err := signify.GenerateKey("acme package key")

sig := sk.Sign(message, signify.SignatureComment("acme-20260815"))
data, err := sig.Marshal()
```

### Embedded signatures

An embedded signature carries the message it covers, so the two cannot drift
apart:

```go
sig := sk.SignEmbedded(checksums, comment)

msg, err := pk.VerifyEmbedded(sig)
```

### Checksum files

BSD tagged form, as written by OpenBSD `sha256(1)` and GNU `sha256sum --tag`.
The untagged GNU form is accepted on input.

```
SHA256 (s3_v1.1.5_linux_amd64.ptar) = 5f4d974923d185c163...
```

`CheckFiles` is the `signify -C` flow: verify the signed list, then check each
listed file against it. The signature is checked before any file is consulted,
so callers always work from signed data.

```go
err := signify.CheckFiles(pk, sig, open)  // open resolves a name to its bytes
```

This package never touches the filesystem: callers supply an `Opener`.

### Key numbers

Every key carries an 8-byte number, copied into each signature it makes. A
verifier can therefore select the right key without being told which one, which
is what makes key rotation invisible to users: trust several keys at once, and
each signature finds its own.

```go
if pk.KeyNum == sig.KeyNum { /* this key made that signature */ }
```

Note `Verify` reports `ErrKeyMismatch` for a signature made by a different key,
distinctly from `ErrBadSignature` for one that fails to verify — the two mean
different things to a caller choosing among several trusted keys.

## Command

```
signify -C [-q] -p pubkey -x sigfile [file ...]
signify -G [-n] [-c comment] -p pubkey -s seckey
signify -S [-e] [-x sigfile] -s seckey -m message
signify -V [-eq] [-x sigfile] -p pubkey -m message
```

```sh
go build ./cmd/signify
```

Flags and semantics follow `signify(1)`, so it substitutes for the OpenBSD tool
on systems that lack it.

## Notes

`SignatureComment` takes a bare key name. `signify(1)` derives the comment from
the secret key path it was given, which publishes the signing host's directory
layout in every signature; passing a basename avoids that.

Secret keys are written `0600`. A passphrase-protected key uses bcrypt_pbkdf,
as signify does; `-G -n` writes an unencrypted key for unattended signing.

## Testing

```sh
go test ./...
```

Fixtures under `testdata/` come from the real toolchain — keys generated by
`gosignify -G`, and a signed artifact fetched from `plakar.io/dist` — so the
tests fail if this package stops agreeing with signify itself.
